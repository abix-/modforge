# abioticfactor-mod open issues

Naming correction 2026-09-12: this is a generic AI player system inside the
existing AbioticFactorMod. Sophia is the first named profile, not the system.
The ai_player module and ai_player.start/status/stop operations own sessions;
start takes an existing profile directory. Preserve Sophia's current identity
and memory. Initial integration supports one active AI player session; support
for additional concurrent instances remains future work.

Current decision 2026-09-12: Sophia's existing Rust UDP client will run inside
the mod in the human's host game. One game client, one world, Sophia still
joins as a separate LAN player over UDP. Join, spawn, movement, interactions,
respawn and logout remain UDP actions. The mod may read the host's loaded
world and query its dynamic navigation mesh/pathfinding for Sophia. Reuse the
shared route follower; preserve her identity and persistent memory. Network
work must not block the game thread; engine queries must run on the game
thread. This replaces the separate-executable requirement, the prohibition on
host-world navigation access and the local mesh-generation/A* plan below.
Direct host character creation, transform writes and physics-free far movement
are not the chosen approach. This is an approved plan, not implemented behavior.
Earlier design/status paragraphs below are historical where they conflict.

Goal: play on Hard with scaled rewards, raise max skill level from 20 to 100.

Second goal: an AI player. A second player character that lives in the same world by the same rules as the human player, driven by the shared bot through player input. The game places it where it places any joining co-op player. It knows the map layout and the navigation mesh, but learns container contents and enemies only when it sees them. Near the human it walks with player input and obeys every rule. Far from the human it steps along a path the mesh returned, without physics, and never through a door it cannot open or a gap with no link. Operator decision 2026-09-12: the AI player has no restrictions beyond what breaks the game. Every action the human player can take, the AI player can take, story triggers included. When it dies it respawns by the game's own rules, and a bed it sleeps in moves its respawn point like anyone else's. It levels its own skills by doing things, so finding it grinding enemies is expected, not a bug. Operator design 2026-09-12: this game supports co-op, so the bot is a LAN co-op player. The hosted LAN game is a UDP listen server on port 7777 (read live: world URL port 7777, options `listen`, `bIsLanMatch=1`, `MaxPlayers=6`; EOS driver in passthrough; joiners arrive as `IpConnection`). The bot is a client of that port: it connects to `127.0.0.1:7777`, logs in with a name, joins, and does everything a LAN player does over that port, using its own Rust implementation of the UDP protocol in a separate executable. No second game instance, no second world, no second local player on the host, no second copy of the game. The human player is never driven by the mod. The first shipped state is one AI player that walks to a container and takes an item.
